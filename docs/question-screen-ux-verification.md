# Проверка UX экрана вопроса

Изменения реализованы в ветке `question-screen-ux` на commit `143a3a2`.

Проверено на host:

- Jest: **75 наборов, 393 теста**, все прошли.
- Скриптовый регресс: **176 тестов**, все прошли.
- TypeScript: `tsc --noEmit` прошёл.
- ESLint: 0 ошибок, 0 предупреждений после объединения импортов.

Проверенные пользовательские сценарии:

- Поле ответа имеет подпись «Ответ на немецком», placeholder «Ваш ответ» и минимальную высоту 56 dp.
- Пустой ответ не создаёт попытку; Enter и «Проверить» используют один валидатор.
- Символы ä/ö/ü/ß вставляются в позицию курсора и заменяют выделение.
- При открытой клавиатуре группа поля измеряется и прокручивается только на необходимое смещение; повторное событие не накапливает сдвиг.
- Инструкция и серия берутся из текущего вопроса и SQLite; UUID профиля на экране обучения не показывается.
- После ответа доступны карточка и помощник; возврат из помощника, открытого из тренировки, возвращает к сохранённому результату.
- Кнопки вторичного действия имеют доступную область не менее 48 dp и корректно объявляют disabled-состояние.
- Evidence-validator проверяет SHA APK, screenshot/hierarchy, закреплённую IME, геометрию поля и кнопки, отсутствие перекрытия клавиатурой и capture после отправки.

Android-эмулятор и Pixel 9 Pro XL в этой среде **not-verified**: команды `adb` и `maestro` недоступны, поэтому APK, закреплённая Gboard, fontScale 1.5, TalkBack и физический Pixel не объявляются пройденными. Для завершения нативного блока нужно собрать release APK, подготовить локальный API 36 AVD, выполнить `question-ui` и затем полный regression runner с отдельными каталогами evidence.
