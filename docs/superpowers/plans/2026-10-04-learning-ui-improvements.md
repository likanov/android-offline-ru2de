# Learning UI Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, preserving the user's earlier multi process execution preference. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать основной путь обучения понятным новичку: быстро начать занятие, понять требуемый ответ, получить помощь после ошибки, увидеть прогресс и результат занятия.

**Architecture:** Доработать существующие React Native экраны и общие элементы. Учебные состояния, попытки и XP остаются в SQLite; интерфейс получает прогресс и итоги через отдельный репозиторий чтения. Новая схема БД и новые зависимости для этих исправлений не требуются.

**Tech Stack:** React Native 0.85.3, React 19.2.3, Expo 56.0.23, expo-sqlite 56.0.6, TypeScript, Jest, React Native Testing Library, Maestro, Android API 36.

## Global Constraints

- Приложение работает без интернета, профили имеют отдельные словари, занятия, подсказки и прогресс.
- «20 правильных подряд завершают изучение слова. Ошибка до завершения сбрасывает его серию».
- «Затем повторения идут через 1, 3, 7, 14, 30 и 60 дней. Ошибка назначает повторение на завтра, сохраняя завершённое первоначальное изучение».
- «3 ошибки добавляют слово в трудные; 3 правильных подряд убирают его оттуда».
- «Опыт: +10 XP за правильный ответ, +50 XP за первое изучение слова; уровень каждые 500 XP».
- Дневная цель — от 1 до 200 правильных ответов. Дневная цель и серия 20 подряд относятся к разным показателям; интерфейс должен обозначать это словами.
- Артикль и цвет рода скрыты до ответа в заданиях на артикли. Прилагательные не получают род существительного.
- Ввод сохраняет проверку умлаутов и ß; допускает NFC, изменение регистра и пробелов. Требуемый ответ не показывается в placeholder.
- Подсказка, карточка, звук, просмотр итогов и продолжение занятия не начисляют XP. Повторная отправка принятой попытки не создаёт второй результат.
- Существующие данные, вручную выбранные иконки и вариант «Без иконки» сохраняются. Изменения интерфейса не сбрасывают обучение.
- Сохранить applicationId `com.personal.germanvocabulary`, совместимость резервных копий и существующие стабильные testID. Новые проверки дополняют обязательную матрицу.
- Для изменения поведения обязателен цикл RED → GREEN → REFACTOR. Перед передачей нового APK выполнить полную регрессию полной версии в Android-эмуляторе с SQLite, аудио и реальной локальной моделью.

## Предлагаемый интерфейс

Это конкретизация рекомендаций аудита для реализации. Названия и расположение ниже — проектные решения этого плана.

| Экран | Порядок основного содержимого |
| --- | --- |
| Сегодня | Заголовок и имя профиля → дневная цель и её прогресс → продолжение сохранённого занятия, если оно есть → изучение и повторение → компактная статистика → свёрнутый редактор цели. |
| Словарь | Заголовок и имя профиля → поиск → компактный выбор «Все / В процессе / Изученные» → «Фильтры» и «Добавить слово» → строки слов с состоянием и серией. Темы и трудность скрыты в раскрываемом блоке. |
| Задание | Режим изучения или повторения → инструкция → слово и допустимые подсказки → прогресс текущего слова → ответы → второстепенные карточка и помощь. |
| Ответ принят | Правильность → ожидаемый ответ → обновлённый прогресс и XP → «Продолжить» → «Разобрать слово» и «Помоги запомнить». |
| Карточка | Цвет рода и выбранная иконка → слово и перевод → серия или статус «Изучено» с датой повторения → компактное прослушивание → пример, заметки, подсказки → возврат по месту открытия. |
| Занятие завершено | Правильные ответы, ошибки, XP, первые изученные слова и текущий прогресс слов занятия → «На сегодня» → «Следующие слова», если доступны. |

Нижние вкладки: «Сегодня», «Словарь», «Учить», «Ещё». Для вкладки обучения сохранить `nav-training`; её видимое и доступное имя — «Учить». Заголовок самого экрана может оставаться «Тренировка». При открытой системной клавиатуре панель скрывается и возвращается после закрытия.

Основное действие имеет заливку. Вспомогательные действия имеют спокойный вторичный стиль. Состояния ошибки и успеха различаются текстом и символом, а не только цветом.

## Review Focus

1. Помощь после уже принятого ответа и force-stop: возвращается тот же attemptId и результат, XP не меняется. Задачи 3 и 8.
2. Редактирование слова в карточке, открытой из занятия: лексическое изменение отменяет устаревшее задание; косметическое сохраняет прогресс и принятый результат. Задачи 3 и 6.
3. Переключение профиля во время загрузки прогресса или итогов: поздний результат чужого профиля не появляется. Задачи 2, 4 и 7.
4. Пустой словарь, все слова изучены или повторений нет: доступны понятное объяснение и следующий полезный шаг; новый пустой сеанс не запускается. Задачи 4, 5 и 7.
5. Длинные слова и имена, 320 dp, шрифт 1.5, закреплённая клавиатура и смена масштаба при открытом приложении: текст читаем, действия доступны, меню восстанавливается. Задачи 1 и 8.

## Команды итоговой проверки

Из корня проекта:

```sh
./scripts/toolchain.sh npm test -- --runInBand
./scripts/toolchain.sh npm run test:scripts
./scripts/toolchain.sh npm run typecheck
./scripts/toolchain.sh npm run lint
./scripts/toolchain.sh npm run build:android
```

Полный прогон после подготовки реальных входных файлов, которые описаны в `docs/emulator-regression.md`:

```sh
./scripts/toolchain.sh npm run test:android:regression -- \
  --apk "$PWD/android/app/build/outputs/apk/release/app-release.apk" \
  --model-dir "$PWD/../../work/model-preparation" \
  --avd GermanVocabulary_API36 \
  --previous-apk "$PWD/../../work/android-regression/upgrade-source/task5-app-release.apk" \
  --fixture "$PWD/../../work/android-regression/fixtures/regression-backup.json" \
  --observations "$PWD/../../work/android-regression/ui-improvements-observations.json" \
  --report-dir "$PWD/../../work/android-regression/ui-improvements-final"
```

Перед командой проверить путь previous-apk и его provenance; использовать фактический ранее собранный APK исходной версии Task5 с той же подписью. Fixture должен соответствовать дню прогона. Если указанные файлы отсутствуют, подготовить их существующими скриптами, не подменять APK или фикстуру произвольным файлом.

Файл observations содержит фактические `audioAudible`, `languageQuality`, `languageNotes`, `tts`, как описано в `docs/emulator-regression.md`. Подготовить его после проверки звука и настоящих генераций на новом APK; во время итогового прогона повторно сопоставить эти наблюдения с текущими артефактами. Runner читает файл также при проверках и в конце запуска. Если файл не готов, первый прогон остаётся неполным; собрать наблюдения и повторить полный прогон с файлом, сохраняя первый отчёт. Не переписывать статус первого запуска вручную. Код 2 означает неполную проверку, код 1 — провал; для полной регрессии нужен код 0.
