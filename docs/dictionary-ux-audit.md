# Анализ UX словаря и поиска

Проверка от 6 октября 2026 года. Словарь корректно читает данные своего профиля и сочетает поиск с фильтрами, однако компоновка затрудняет основной сценарий: найти слово, открыть карточку и продолжить просмотр. При открытии страницы слова отсутствуют в видимой области, найденная карточка остаётся ниже настроек, а возврат из карточки сбрасывает поиск.

Проверены текущий release APK на Android API 36 и исходники ветки `assistant-practice-implementation`. Использован отдельный профиль AuditUX06 с 40 стартовыми словами и шестью темами. Основной режим — 1080 × 1920 px, 480 dpi, 360 × 640 dp, шрифт 1.0. Дополнительный режим — 320 dp, шрифт 1.5. После проверки восстановлены 480 dpi и шрифт 1.0. Физический Pixel 9 Pro XL и TalkBack в этом проходе не проверялись.

SHA-256 установленного APK: `93e6ab3c485627bf37b29073b4b817c1945b0c3bd70ff8b93b39ff6775d163db`. Базовый коммит: `9034e84c7e3d4d3c1eebe5e8f738df9922d21880`; рабочее дерево содержит ранее сделанные изменения. DictionaryScreen, WordRepository и navigation.tsx не имеют локальных изменений относительно этого коммита. Код приложения и существующий implementation plan в ходе анализа не изменялись.

## Проблемы и приоритеты

P1 — препятствие основному сценарию словаря, которое следует исправить первым. P2 — заметное затруднение следующего этапа. Приоритеты являются оценкой этого аудита.

## Фактические результаты поиска

Поиск выполняется локально, по вхождению непрерывной строки в немецкое слово или русский перевод. Состояние, трудность и тема дополнительно ограничивают результат.

| Запрос | Результат |
| --- | --- |
| Buch, buch, пробелы вокруг BUCH | Buch |
| кни, КНИГА | Buch |
| grün, GRÜN с составным Unicode-умлаутом | grün |
| grun, gruen | 0 |
| Straße | Straße |
| Strasse | 0 |
| das Buch | 0 |
| der | 0 |
| Bücher | 0, хотя множественное число сохранено в карточке |
| ребёнок | Kind |
| ребенок | 0 |
| зелёный | grün |
| зеленый | 0 |
| Buch книга | 0 |
| Только пробелы | Все 40 слов |
| Несуществующее слово, символ % | 0 |

Поиск по множественному числу следует включить в следующий этап. Поиск по заметкам, примерам, опечаткам и сочетанию немецкого слова с переводом может быть отдельным расширением; текущий placeholder этого не обещает.

## Что работает

Проверки SQLite подтвердили поиск без зависимости от регистра, нормализацию NFC и пробелов, поиск по части русского перевода и совместное применение query + state + difficult + topicId. Слово, добавленное другому профилю, не появляется в результатах первого. Эффект загрузки списка использует alive-флаг для игнорирования результата запроса после очистки эффекта.

На эмуляторе ввод Buch обновил счётчик до 1. Экранная клавиатура видима на сохранённом снимке; нижняя навигация при её открытии скрывается. После закрытия клавиатуры запрос остаётся. Карточка открывается, показывает правильный артикль, зелёный маркер среднего рода, перевод, множественное число и пример.

При четырёх последовательных изменениях B → Bu → Buc → Buch диагностическая проверка зафиксировала четыре полных SELECT списка слов. Поиск затем фильтрует строки в JavaScript; все результаты отрисовываются через map внутри ScrollView. На 40 словах задержка не измерялась как проблема. Для больших словарей это риск производительности: требуется отдельная проверка на устройстве, после которой можно выбрать кэширование нормализованных полей, короткую задержку ввода и виртуализированный список. Порядок сейчас задаётся SQLite ORDER BY w.de,w.id; это не сортировка по релевантности и не немецкая алфавитная сортировка — в стартовом наборе Übung находится после weiß.

## Связь с существующим планом

Задача 5 «Компактный словарь» в [плане улучшения интерфейса](superpowers/plans/2026-10-04-learning-ui-improvements.md) уже предусматривает сворачиваемые фильтры, статусы строк, пустой результат и минимум две видимые строки при 360 × 640 dp. DictionaryFilters.tsx и test/ui/dictionary.test.tsx в текущем рабочем дереве отсутствуют; DictionaryScreen сохраняет прежнюю компоновку.

Для следующего выполнения этой задачи следует добавить сохранение контекста при возврате, поиск по артиклю и множественному числу, отдельную нормализацию поисковых вариантов и уточнение смысла «В процессе». Задача 6 уже предусматривает прогресс в карточке и заполнение иконок новых профилей. План в рамках этого анализа не редактировался.

Условия приёмки исправления:

1. При 360 × 640 dp без прокрутки видны поиск, добавление и минимум две строки слов; найденная единственная карточка также видна сразу. С клавиатурой остаётся доступен результат поиска.
2. Путь поиск → карточка → редактирование → возврат сохраняет запрос, выбранные фильтры и позицию списка. Смена профиля не переносит контекст другого словаря.
3. Buch и das Buch находят одну карточку; Bücher находит её по множественному числу; ребенок/ребёнок, gruen/grün и Strasse/Straße находят соответствующие слова. Эти послабления не изменяют проверку ответов в тренировке.
4. Пустой результат объяснён; запрос и фильтры можно сбросить; новый профиль не обозначает все слова как уже начатое обучение без пояснения.
5. Выбранные фильтры различимы визуально и для экранного диктора. При 320 dp и шрифте 1.5 основные подписи читаемы, все действия доступны.

## Проверка и доказательства

Свежий запуск четырёх существующих наборов words, topics, navigation и wordEditor: 22 из 22 тестов прошли. Отдельные диагностические проверки поиска на SQLite и поведения DictionaryScreen: 2 из 2 прошли, зафиксировав текущее поведение, включая перечисленные ограничения. Успех этих проверок не означает исправление UX-проблем или прохождение полного регресса приложения.
